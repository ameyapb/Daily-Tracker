1. THE CORE IDEA
-----------------
Build a lightweight daily activity tracker website, structured like a
Kanban board.

- The board is made of LANES (columns), which the user freely creates,
  renames, reorders, and deletes. Lanes are purely freeform/organizational
  — not tied to status. The user decides what each lane means (e.g.
  "Category X" / "Must-do Today" / "Work"), and can drag a card from any
  lane to any other lane at will. Status (below) is a separate field on
  the card and does not change just because a card moved lanes.

- Each CARD is one task, with metadata:
    - Task name (required)
    - Description (optional, free text)
    - Reminder time — flexible input:
        - Relative: "remind me after N hours" (or minutes/days)
        - Absolute: a specific date + time (deadline)
    - Status: TODO / IN PROGRESS / COMPLETED / DELAYED

- Reminder behavior: when the reminder time is reached, the app fires a
  notification (system/browser notification, and/or a sound). From that
  notification (or from the card itself) the user can:
    - Snooze (push the reminder back by some interval)
    - Mark complete

- Status model: a card can be TODO, IN PROGRESS, COMPLETED, or DELAYED.
  DELAYED is settable both ways: automatically by the system (when now >
  reminder_time and the card is still TODO/IN PROGRESS) and manually by
  the user at any time (e.g. to flag something as delayed before its
  reminder time, or without a reminder set at all).

- Two SYSTEM LANES exist alongside the user's freeform lanes: a DELAYED
  lane and a COMPLETED lane. When a card's status becomes DELAYED or
  COMPLETED, the card physically moves out of its current (user) lane
  and into the matching system lane — it no longer sits in its original
  lane. The DELAYED lane persists (cards stay there until the user acts
  on them). The COMPLETED lane resets every day — cards are cleared off
  the visible board daily but archived (kept in the database, not
  deleted), so completed-task history isn't lost.


2. NOTIFICATIONS (v1: IN-APP BANNER)
----------------------------------------
  - While the app is open in a tab, a client-side timer (setInterval,
    checking every 10–30s) compares "now" against each card's
    `remind_at`.
  - When a card's reminder time is reached, show an in-app banner/toast
    (task name + Snooze and Complete buttons on the banner itself).
    Optionally pair with a short sound (HTML5 Audio API).
  - No backend, service worker, or push infrastructure — just reads
    `remind_at` values already in the database. One polling hook + one
    banner component.
  - If the tab isn't open when the reminder time passes, nothing fires;
    the card should just show as DELAYED next time the app is opened
    (see status model above).

4. FEATURE LIST
-------------------
Core (v1):
  - Create / rename / reorder / delete lanes
  - Create / edit / delete cards within a lane
  - Card fields: name, optional description, optional reminder
    (relative "+N hours" or absolute date+time), status
  - Drag-and-drop cards between any lanes, freely (lanes don't imply

    moves into the matching system lane when its status changes to
    DELAYED or COMPLETED. DELAYED lane persists; COMPLETED lane resets

  - Notification at reminder time via in-app banner + optional sound
    (see section 2)
  - Snooze (from banner or from the card) and Complete actions

5. UX DECISIONS (resolved — follow these, don't re-derive)
-----------------------------------------------------------
These decisions shape the interaction design and should guide implementation,
not just visuals.

- System-lane transitions (card becomes DELAYED or COMPLETED):
    No live "flying card" animation. The card simply is in the system lane
    next time the board is viewed/re-rendered. Simplest correct behavior —
    the reminder modal (below) is what actually informs the user something
    happened, not board motion.

- DELAYED lane presentation:
    Visually flagged, not styled like a plain user lane — e.g. a warm/red
    accent on the lane header and a count badge — so an accumulating
    backlog of delayed tasks is obvious at a glance rather than blending
    into the board. (The lane still has no sorting/collapsing in v1; revisit
    if it gets unwieldy — see non-goals.)

- Reminder notification (in-app, tab open):
    A centered modal that blocks the board and requires an explicit action
    (Snooze / Complete / dismiss) — not a passive toast. This is a
    single-user task tracker, so a fired reminder should demand a decision
    rather than being easy to miss in a corner.
      - Queuing: if multiple reminders fire before the user returns to the
        tab (or fire close together), do NOT stack multiple modals. Show
        ONE modal listing all fired reminders as a short list, each row
        with its own inline Snooze / Complete. This keeps clearing a
        backlog fast and avoids a gauntlet of sequential dialogs.

- Card create/edit:
    A modal dialog, opened from a "+" on a lane (create) or from clicking
    a card (edit). Holds all fields: name, description, reminder, status.
    Chosen over inline/expand-in-place for consistency — one predictable
    place to manage a card's full data, regardless of lane width or how
    many fields are filled in.

- Lane header styling:
    Plain and minimal — text label only, no user-assignable color. Visual
    weight stays on cards and status/system lanes, not on organizational
    lanes. (Contrast with the DELAYED lane above, which is intentionally
    flagged because it's a system lane the user needs to notice, not an
    organizational one.)

7. NON-GOALS (keep this lightweight)
---------------------------------------
  - Single-user only — no accounts, no login, no auth. No team/
    collaboration features (sharing boards, assigning tasks to others).
  - No native mobile app or PWA — a plain browser tab is enough for v1.
  - No heavy state-management library needed at this scale (React
    Query / Zustand or similar lightweight tools would be plenty;
    avoid Redux-scale ceremony for a personal Kanban tracker).
